# Issue tracker: GitHub

This repository tracks implementation work in GitHub Issues. Prefer `gh issue view`, `gh issue create`, and `gh issue comment` from the repository checkout. Check existing issues before creating a new one, keep each issue focused, and do not edit closed planning issues #1–#17.

## Conventions

- Create a focused issue when implementation scope is ready to begin; do not recreate the closed planning epics.
- Reference `docs/planning/PLANNING_CONTRACT.md` and applicable architecture documents in implementation issues.
- Use one coherent issue per branch and keep pull requests linked to the issue.
- PRs are not a separate request or triage surface.
- Do not close an implementation issue while its PR is awaiting human review unless the repository workflow explicitly requires it.
